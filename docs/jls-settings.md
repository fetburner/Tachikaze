# join_logo_scp の設定と既知の失敗モード

→ 入口: [overview.md](overview.md) / 仕組みの背景: [cm-detection.md](cm-detection.md)

**CM 検出が外れたときはこの文書を読む。** 実測で効果を確認した設定のみ記載。

## 既定で付与すべきオプション

```bash
join_logo_scp -inscp scp.txt -incmd JL/JL_標準.txt -o trim.avs -oscp detail.jls \
              -set autocm_sub 11 \
              -set param_cuttr 1
```

`-inlogo` は既定では付けない。省略すると全フレームがロゴ表示中とみなされる。`analyze --logo <path.lgd>` を指定すると自前実装のロゴ検出（`src/logo/`）を通し、検出フレーム割合が閾値以上、かつ logoframe テキストが空でないときだけ `-inlogo` を渡す（詳細は `src/analyze.rs::detect_logo`/`inlogo_decision` の doc comment）。割合だけでは判定できない（`logo_frames` の数え上げと `text` の出力は別経路のため、割合が閾値以上でも `text` が空になるケースがある）。対象の mp4 には局ロゴが残っていることが多い（[measurements.md](measurements.md)「ロゴの残存」）。

**`autocm_sub`/`param_cuttr` の既定値はロゴあり・なしで変えない**（実測・根拠は下記「ロゴありでの比較・既定値」）。この節の `autocm_sub`/`param_cuttr` の実測（次の2小節）はいずれも**ロゴ無し（`-inlogo` 省略）の状態**で得たもの。ロゴありでの実測・比較は下記の専用節を参照。

### `autocm_sub` : 10 → 11（先頭の CM を切る、ロゴなしでの実測）

```
Default autocm_sub 10   # ロゴなし時の補助設定
                        #（0:なし 1:先頭15秒単位構成は少数でもCM化 +10:45秒は含めない）
```

既定値 `10` は「+10」の部分だけで、**「1: 先頭 15 秒単位構成は少数でも CM 化」が無効**。`11` にすると有効になる。

**実測（ファイル B）**: 番組冒頭の 15 秒 × 2 = 30 秒が `:L`（本編扱い）と判定されて残っていたのが、`:CM` に変わって除去された。

```
既定:          Trim(74,6127)  ++ …
autocm_sub=11: Trim(976,6127) ++ …     ← 先頭 30 秒が消えた
```

**なぜ必要か**: 番組の先頭は文脈（前後の本編）がないため、15 秒単位の構成が CM か本編かを判断できない。ロゴがあれば判別できるが、ロゴなしではヒューリスティックに頼るしかない。

### `param_cuttr` : 0 → 1（番宣を切る、ロゴなしでの実測）

```
Default param_cuttr 0   # 予告等終了後のロゴ付き15秒単位構成（0:残す 1:カット）
```

**実測（ファイル B）**: 末尾に `Trailer(cut-cancel)` が 35 秒 + 15 秒 = 50 秒残っていた。

`cut-cancel` は「番宣としてカット対象と**判定はした**が、設定でキャンセルした」という意味（`JlsDataset.cpp` で `flagCutTR` を見て文字列を切り替えている）。つまり検出は成功していて、方針の設定だけの問題。

```
既定:          … ++ Trim(48476,50872)
param_cuttr=1: … ++ Trim(48476,49374)   ← 末尾 50 秒が消えた
```

## 残るもの（意図的）

`param_cuttr=1` にしても、`(add)` が付いたものは残る:

```
48476  48625    5  :Trailer(add)     ← 次回予告
48626  49074   15  :Trailer(add)
49075  49374   10  :Sponsor(add)     ← 提供クレジット
```

`JL_標準.txt` は次回予告と提供クレジットを本編扱いにする方針。消したいなら別途設定が必要（好みの問題なので既定は変えない）。

## ロゴありでの比較・既定値

`analyze --logo`（自前ロゴ検出）で、実ファイル2本（BS11・TOKYO MX2。詳細は [measurements.md](measurements.md)「ロゴあり/なしの比較」）の `-inlogo` あり/なしを比較した。

### `detail.jls` のラベルの変化（BS11、`--logo` あり/なし）

`:L`（ロゴ有＝情報なし）だった長い本編ブロックが `:Mix`（ロゴ有・ロゴ無混合、ロゴ秒がわずかに短くなる）に変わった。加えて、末尾の 5 秒区間が `:Nologo(cut)`（ロゴなしでは CM 扱いで除去）から `:Endcard(add)`（ロゴありではエンドカードと判定され本編に追加）に変わり、Trim にその区間が追加された（余分に残る量 13.5s → 16.5s）。**エンドカード判定はロゴの有無を条件にしている**ため、ロゴを渡さないと検出できない構成だった。誤差列（4 列目）はどちらも既に 0〜-1 フレームで小さく、この 1 本では「誤差が 0 に近づく」効果は観測できなかった（元々の無音シーンチェンジ検出の精度が高かったため）。

TOKYO MX2（720x480、ロゴが非常に薄い）では `--logo` を指定しても検出フレーム割合が 0 になり `-inlogo` を渡さないフォールバックに落ちた（下記「見ていないこと」）。この場合 Trim / detail.jls は無ロゴ実行と完全に一致する。

### `autocm_sub` / `param_cuttr` はロゴありでは無効果（実測、既定値は変えない）

BS11 に `--logo` を指定した状態で `autocm_sub`（10/11）× `param_cuttr`（0/1）の 4 通りを試したところ、**`trim.avs` と `detail.jls` がバイト単位で完全に一致した**（4 通りすべて同じ出力）。この実測ファイルには `:Trailer(cut-cancel)` も「番組冒頭 15 秒 × 2」の構成も現れなかったため、そもそも両設定の分岐が発火する箇所自体が無かった（ロゴありだと `$NOLOGO=0` になり、冒頭の 15 秒判定はロゴの有無で行われるため、ロゴなし救済用の `autocm_sub` の「1」ビットが効く場面が減るという理屈には合う）。

**決定: ロゴありでも既定値を変えない（`autocm_sub=11`、`param_cuttr=1` のまま）。** 根拠: (1) 実測で効果が確認できなかった以上、`--logo` の有無で `-set` を分岐させる複雑化に見合う実測上の利益が無い、(2) 変えても実害が無いことは確認できている（BS11 で差が出ないことを確認済み）。**見ていないこと**: 1 局・1 本のみで検証しており、`(cut-cancel)` や冒頭 15 秒×2 の構成が実際に現れるロゴあり番組では、この2設定が効くかどうかは未確認。将来そうした番組で差が出たら値を分けることを検討する。

### `-CutMrgIn` / `-CutMrgOut`（実測、CLI には追加しないと決定）

`-CutMrgIn`/`-CutMrgOut` は join_logo_scp の起動オプションであり `-set` 変数ではないため、`tachikaze` の `--jls-set` からは渡せない。`JL_標準.txt` は `-CutMrgWI 2`/`-CutMrgWO 2`（自動判断）を既定にしており、実行時に `auto detect CutMrgIn=... CutMrgOut=...` を stdout に出す。BS11 のキャッシュ済み `scp.txt`/`logoframe.txt` に対して `join_logo_scp` を直接実行し確認した:

```
auto detect CutMrgIn=5 CutMrgOut=8
```

`-CutMrgWI 0 -CutMrgWO 0`（自動判断を切り、指定値をそのまま使う）にして `-CutMrgIn`/`-CutMrgOut` を `0`・`20` に強制すると、自動検出（`5`/`8`）と比べて **`trim.avs` は完全に一致し、変化しなかった。一方 `detail.jls` のラベルは変化する**（`-inlogo logoframe.txt` を渡した状態で確認。渡さない場合は `trim.avs`/`detail.jls` とも 3 通りすべて完全一致し、この差は再現しない）。`0` では `:Mix` のロゴ秒が短くなり（`500→497`、`756→754`）、`20` ではさらに `:Sponsor(add)` が `:L` に変わり、1 つの `:Mix` が 3 行に分割される:

```
$ diff <自動検出のdetail.jls> <CutMrgIn/Out=20のdetail.jls>
3c3
<   2481   2629    5  -1    5 :Sponsor(add)
---
>   2481   2629    5  -1    5 :L
7c7,9
<   4428  19832  514   0  500 :Mix
---
>   4428  10291  196 -10  196 :Mix
>  10292  10438    5  -3    0 :Sponsor(add)
>  10439  19832  313  13  308 :Mix
11c13
<  21631  44556  765  -1  756 :Mix
---
>  21631  44556  765  -1  758 :Mix
```

`-CutMrgWI`/`WO` を既定の `2`（自動判断）のままにして `-CutMrgIn`/`-CutMrgOut` だけ振っても、同じ diff になった（自動判断が `-CutMrgIn`/`-CutMrgOut` の指定値を上書きしないことも合わせて確認できた）。

**決定: CLI に `--jls-cut-mrg-in`/`--jls-cut-mrg-out` のようなフラグを追加しない。** 根拠は [architecture.md](architecture.md)「未解決事項」に記録する（実測結果自体はここに残す。「なぜ実装しないと決めたか」の記述の一元化のため理由の本文は architecture.md 側）。中間表現（`detail.jls` のラベル・ロゴ秒）は `-CutMrgIn`/`-CutMrgOut` を振ると動くが、最終出力である `trim.avs` には届かなかった、というのがこの決定の実測上の根拠になる。**見ていないこと**: 1 局のみの実測で、`0`〜`20` フレームの範囲でしか振っていない。`-CutMrgWI`/`WO=0` で自動判断を切ってもなお `detail.jls` が変化した以上、「シーンチェンジがロゴ境界にあるので自動判断が無効化されて当然」という説明は成り立たない。`trim.avs` が変わらなかった理由は未調査（ロゴ境界とシーンチェンジのズレが 20 フレーム以内では、`detail.jls` 側の変化が Trim の境界を動かすところまで届かない、という実測にとどまる）。局によっては固定遅延が大きく、値を振ればより差が出る可能性は残る。

## 既知の失敗モード: 内部区切りのない CM ブロックの見逃し

### 症状

**実測（ファイル C）**: 120 秒の CM ブロックが 1 つだけ CM と判定されなかった。他の 3 ブロックはフレーム単位で同じ長さ（3596〜3597 フレーム）なのに、1 つだけ本編扱い。

### 原因

そのブロックの**内部に無音シーンチェンジが 1 つも検出されていない**。他の CM ブロックは内部に 15/30 秒ごとの区切り（個々の CM の境界）があるため「15 秒単位構成の連続」として認識されるが、このブロックは **120 秒の単一構成**に見える。

関連する設定:

```
Default autocm_maxprd 60   # 指定秒を超える構成は15秒単位でもCM扱いにしない
```

### 試して効かなかったこと

| 試行 | 結果 |
|---|---|
| `chapter_exe -m` を 50 → 100 / 200 / 400 に緩める | 冒頭 30 分の候補は 4 → 32 個に増えたが Trim は変化なし |
| `-set autocm_maxprd 120` / `180` | 変化なし |
| `-set autocm_code 10`（最大） | 変化なし |
| `-set autocm_scopex 3600` | 変化なし |
| 上記の組み合わせ | 変化なし |

`detail.jls` を見ると、該当位置が**構成の区切りとして認識される前段階で落ちている**（該当区間を含む 1786 秒が単一の `:L` 構成になっている）。CM 判定側の設定では届かない。

### 対処

1. **手動で Trim を修正する。** Trim は 1 行のテキストなので書き換えは容易。`analyze` と `cut` を分けたコマンド設計にしている理由がこれ
2. **見逃し候補の自動警告を見る（実装済み）。** `analyze --report` が以下のヒューリスティックで警告を出す（`src/report/missed.rs::find_missed_candidates`）:

   > 検出済み CM ブロックの長さを集め、**同じ長さの未カット区間**があれば「見逃し候補」として警告する

   ファイル C では全 CM ブロックが 3596〜3597 フレームだったため、この規則だけで機械的に検出できた（この実測値をそのままテストケースにしてある）。ブロック長が揃わない番組では効かない

**ロゴありでの見逃し警告（実測）**: このヒューリスティックは `.jls` のラベルを見ず、Trim のギャップ長と保持区間内の長さの一致だけで判定する（`src/report/missed.rs`）ため、ロゴの有無で判定ロジック自体は変わらない。BS11・TOKYO MX2 の実測（上記「ロゴありでの比較・既定値」）では `--logo` あり/なしのどちらでも見逃し候補は 0 件で、誤警告の増加は確認できなかった。見ていないこと: 検出済み CM ブロックの長さが揺れる（＝このヒューリスティックの前提が成立しにくい）番組でロゴありを試していないため、一般的に誤警告が増えないと結論づけることはできない。

## 局ごとの JL コマンドファイル

`JL/` ディレクトリに局別のルールファイルがある（`JL_標準.txt` 23 KB、`JL_ATX.txt` 32 KB、`JL_NHK.txt`、`JL_MBS.txt` など）。Amatsukaze はサービス（放送局）ごとに選択する仕組みを持っている（`AmatsukazeServer/Server/EncodeServer.cs` でディレクトリを監視し、`TranscodeWorker.cs` でプロファイル → サービス設定の順にフォールバック）。

**現状は全ファイルで `JL_標準.txt` を使って十分な結果が出ている。** 局別の切り替えは必要になってから考える。

`JL_前後大幅カット.txt` という前後を大きく切るプリセットもあるが、中身は `Abort E/S` によるロゴ位置基準の処理が主体で、ロゴなしでは `longcut_by_auto`（推測構成区切りによるカット、既定 0）しか効かない。**未検証。**

## `detail.jls` の読み方

4 列目（15 秒格子からの誤差フレーム数）が**検出の確信度の指標**になる。0 に近ければ構成推測が自信を持っている。

```
開始   終了  秒数 誤差 ロゴ秒 ラベル
6128  6577   15    0    0 :CM      ← 誤差 0。確度が高い
49375 50437  35   14   35 :Trailer(cut-cancel)   ← 誤差 14。怪しい
```

ラベル一覧は [cm-detection.md](cm-detection.md) を参照。
