# join_logo_scp の設定と既知の失敗モード

→ 入口: [overview.md](overview.md) / 仕組みの背景: [cm-detection.md](cm-detection.md)

**CM 検出が外れたときはこの文書を読む。** 実測で効果を確認した設定のみ記載。

## 既定で付与すべきオプション

```bash
join_logo_scp -inscp scp.txt -incmd JL/JL_標準.txt -o trim.avs -oscp detail.jls \
              -set autocm_sub 11 \
              -set param_cuttr 1
```

`-inlogo` は**付けない**（delogo 済みのため）。省略すると全フレームがロゴ表示中とみなされる。

### `autocm_sub` : 10 → 11（先頭の CM を切る）

```
Default autocm_sub 10   # ロゴなし時の補助設定
                        #（0:なし 1:先頭15秒単位構成は少数でもCM化 +10:45秒は含めない）
```

既定値 `10` は「+10」の部分だけで、**「1: 先頭 15 秒単位構成は少数でも CM 化」が無効**。`11` にすると有効になる。

**実測（ファイル B）**: 番組冒頭の 15 秒 × 2 = 30 秒が `:L`（本編扱い）と判定されて残っていたのが、`:CM` に変わって除去された。

```
既定:          Trim(74,6127)  ++ …
autocm_sub=11: Trim(976,6127) ++ …     ← 先頭 30 秒が消えた
```

**なぜ必要か**: 番組の先頭は文脈（前後の本編）がないため、15 秒単位の構成が CM か本編かを判断できない。ロゴがあれば判別できるが、ロゴなしではヒューリスティックに頼るしかない。

### `param_cuttr` : 0 → 1（番宣を切る）

```
Default param_cuttr 0   # 予告等終了後のロゴ付き15秒単位構成（0:残す 1:カット）
```

**実測（ファイル B）**: 末尾に `Trailer(cut-cancel)` が 35 秒 + 15 秒 = 50 秒残っていた。

`cut-cancel` は「番宣としてカット対象と**判定はした**が、設定でキャンセルした」という意味（`JlsDataset.cpp:2640` 付近、`flagCutTR` を見て文字列を切り替えている）。つまり検出は成功していて、方針の設定だけの問題。

```
既定:          … ++ Trim(48476,50872)
param_cuttr=1: … ++ Trim(48476,49374)   ← 末尾 50 秒が消えた
```

## 残るもの（意図的）

`param_cuttr=1` にしても、`(add)` が付いたものは残る:

```
48476  48625    5  :Trailer(add)     ← 次回予告
48626  49074   15  :Trailer(add)
49075  49374   10  :Sponsor(add)     ← 提供クレジット
```

`JL_標準.txt` は次回予告と提供クレジットを本編扱いにする方針。消したいなら別途設定が必要（好みの問題なので既定は変えない）。

## 既知の失敗モード: 内部区切りのない CM ブロックの見逃し

### 症状

**実測（ファイル C）**: 120 秒の CM ブロックが 1 つだけ CM と判定されなかった。他の 3 ブロックはフレーム単位で同じ長さ（3596〜3597 フレーム）なのに、1 つだけ本編扱い。

### 原因

そのブロックの**内部に無音シーンチェンジが 1 つも検出されていない**。他の CM ブロックは内部に 15/30 秒ごとの区切り（個々の CM の境界）があるため「15 秒単位構成の連続」として認識されるが、このブロックは **120 秒の単一構成**に見える。

関連する設定:

```
Default autocm_maxprd 60   # 指定秒を超える構成は15秒単位でもCM扱いにしない
```

### 試して効かなかったこと

| 試行 | 結果 |
|---|---|
| `chapter_exe -m` を 50 → 100 / 200 / 400 に緩める | 冒頭 30 分の候補は 4 → 32 個に増えたが Trim は変化なし |
| `-set autocm_maxprd 120` / `180` | 変化なし |
| `-set autocm_code 10`（最大） | 変化なし |
| `-set autocm_scopex 3600` | 変化なし |
| 上記の組み合わせ | 変化なし |

`detail.jls` を見ると、該当位置が**構成の区切りとして認識される前段階で落ちている**（該当区間を含む 1786 秒が単一の `:L` 構成になっている）。CM 判定側の設定では届かない。

### 対処

1. **手動で Trim を修正する。** Trim は 1 行のテキストなので書き換えは容易。`analyze` と `cut` を分けたコマンド設計にしている理由がこれ
2. **見逃し候補の自動警告を見る（実装済み）。** `analyze --report` が以下のヒューリスティックで警告を出す（`src/report/missed.rs::find_missed_candidates`）:

   > 検出済み CM ブロックの長さを集め、**同じ長さの未カット区間**があれば「見逃し候補」として警告する

   ファイル C では全 CM ブロックが 3596〜3597 フレームだったため、この規則だけで機械的に検出できた（この実測値をそのままテストケースにしてある）。ブロック長が揃わない番組では効かない

## 局ごとの JL コマンドファイル

`JL/` ディレクトリに局別のルールファイルがある（`JL_標準.txt` 23 KB、`JL_ATX.txt` 32 KB、`JL_NHK.txt`、`JL_MBS.txt` など）。Amatsukaze はサービス（放送局）ごとに選択する仕組みを持っている（`AmatsukazeServer/Server/EncodeServer.cs:2007` でディレクトリを監視、`TranscodeWorker.cs:886` でプロファイル → サービス設定の順にフォールバック）。

**現状は全ファイルで `JL_標準.txt` を使って十分な結果が出ている。** 局別の切り替えは必要になってから考える。

`JL_前後大幅カット.txt` という前後を大きく切るプリセットもあるが、中身は `Abort E/S` によるロゴ位置基準の処理が主体で、ロゴなしでは `longcut_by_auto`（推測構成区切りによるカット、既定 0）しか効かない。**未検証。**

## `detail.jls` の読み方

4 列目（15 秒格子からの誤差フレーム数）が**検出の確信度の指標**になる。0 に近ければ構成推測が自信を持っている。

```
開始   終了  秒数 誤差 ロゴ秒 ラベル
6128  6577   15    0    0 :CM      ← 誤差 0。確度が高い
49375 50437  35   14   35 :Trailer(cut-cancel)   ← 誤差 14。怪しい
```

ラベル一覧は [cm-detection.md](cm-detection.md) を参照。
